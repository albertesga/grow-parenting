Issue Nº 03 — Primitives

The fourteen building blocks everything else is made of.

Buttons, inputs, cards, modal, sheet, toast, phone frame, bottom nav with the central FAB, sticker, tag, pull-quote. No borders, generous radii. Each primitive on its own tinted page so you can see how it feels at rest.

§ A — Button

One shape, eight roles, three sizes.

Always pill-shaped. Hierarchy is built with fill (ink → paper → ghost) and tinted fills for context (coral for primary CTA, mint for confirmation). The link variant carries the hand-underline.

§ G — Decisions

Two checks before Session 04.

Session 04 builds product components: TimelineTrack, MonthCard with VacunaSection, OMSCurve, ChatBubble, QuickLogGrid, 5SChecklist, CryClassifier, Mode3AMRoute, LessonCard.
Decision · 06 · Pill-shape buttons

Adopt fully pill-shaped buttons (radius 999) as default?

Editorially they read softer than rounded-rectangles and they pair well with the tinted-box pattern. The alternative would be radius 16 (still rounded, more "app-like"). Pill is recommended.

Decision · 07 · Bottom Nav central FAB

Coral FAB (60 px) lifted from the centre, with "Log" label below — keep it?

It's the only place coral-base appears in the chrome. The intent: Quick Log is the single most-frequent caregiver action. If you'd rather have a sixth tab without lifting, say so.

Decision · 08 · Status bar + FAB sizes — frozen

Adopt one canonical status bar (10/16/6 px padding · 9px font) and two FAB sizes (60 px standalone · 35 px in-navbar)?

Currently each Flow file is re-implementing the status bar with slightly different padding. The standalone FAB has the coral shadow; the in-navbar FAB doesn't (it lives in a tinted strip and the shadow would compete). Recommendation: freeze both here as .status and .fab-standalone / .fab-nav, then any flow file imports rather than redefines.

Decision · 09 · Calendar primitives in §H

Promote the eleven new components from the Calendario rebuild into Primitives?

The horizontal scrubber, sub-tabs, range bar, canon-opt selector, diary-entry list and confirmation block were all introduced in one session inside Flows. They're general-purpose temporal vocabulary — any future module (medication timeline, school year, custody calendar) should use them. Promoted above as §H so the next session inherits the language.
